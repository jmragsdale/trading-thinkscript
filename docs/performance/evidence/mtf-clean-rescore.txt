## Question

The farm's live-ready headline — **MNQ+MYM 91.8% pass / 6.0% fail / funded-per-slot 1.383** —
was produced by `scripts/score_mtf_ote_package_exact_rules.py` reading
`data/{MNQ,MYM,MGC}_london_enriched.csv`. The 2026-07-22 memo established those CSVs are
written by `MTF OTE/mc_audit/run_volume_analysis.py:84` from `ote_mc_audit.gen_trades`, the
same generator that carries the B5 lookahead leak, and that they bear the leak's WR signature
(MNQ 48.9% / MYM 50.1%) versus the clean engine's 33–36%.

**Does the incumbent package survive when only the trade generator is replaced with a
leak-free one?** Prior on record: no (~10–18% pass), which would mean the farm has no
validated live strategy. This session decides it.

## Method

The campaign scorer is held **byte-fixed**: the same helper functions (`fill_weekdays`,
`summarize`, `daily_soft_metrics`, `worst_start_year_edge`, `gate_status`), the same
`config/exact_prop_rules/myfundedfutures_50k_builder_default_eval.json`, the same combined
package rules (5 entries/day, −2.5R, +4.5R, 1R=$200), the same rolling-start / 40-weekday
timeout conventions, and the same `eval_campaign_metrics` code. **Only the trade generator is
swapped**, so any delta is attributable to the leak rather than to methodology drift.

| | trade source |
|---|---|
| control (`leaked`) | `data/{sym}_london_enriched.csv` |
| treatment (`clean`) | `analysis/independent_exec_audit_2026_07_22/engine_v3.py`, `Cfg(sym, htf=15, chart=1)` |

engine_v3 is run at the **incumbent's own 15/1 geometry** and matching parameters — entry fib
0.705, stop 0.10×ATR, tp fib 0.0, bias lookback 20, sessions 03:00–05:00 / 09:30–12:00 /
14:00–15:55 ET (`ote_mc_audit.py:32-50` BASE_GEN vs `engine_v3.py:111-131` Cfg). It applies
1-minute intrabar sequencing, stop-first on ambiguous bars, no fill before a resting order,
and no fill on the arm bar. Its MNQ 15/1 baseline reproduces the 2026-07-22 validated figures
digit-for-digit (n=3273 / WR 34.52% / gPF 1.145 / netPF 0.923), and invariants I1/I4 are clean
on every leg.

**Harness validity check.** The control run reproduces the published headline **exactly** —
MNQ+MYM 0.9182 pass / 0.0604 fail / slot 1.3832, and MNQ-only 0.9050 / 0.0544 / 1.067. The
scorer is therefore doing what it did when the headline was published; the only thing that
changes below is the trades fed into it.

### Attribution: it is the leak, not engine strictness

The obvious alternative explanation is that engine_v3's extra constraints (resting-order
requirement, bias filter) are what depress the clean numbers. Ablated directly:

| leg | strict (default) | no resting-order req | no bias filter | both relaxed |
|---|---|---|---|---|
| MNQ 15/1 | n=3,273 WR 34.52% | n=3,641 WR 34.22% | n=4,031 WR 35.82% | n=4,378 WR 34.72% |
| MYM 15/1 | n=2,977 WR 36.31% | n=3,382 WR 35.04% | n=3,797 WR 35.98% | n=4,200 WR 34.88% |

Relaxing every constraint drives trade counts **past** the leaked lists' 4,011 / 3,889 while
WR stays inside 34.2–35.8% (MNQ) and 34.9–36.3% (MYM). No combination of fill-model
permissiveness produces the leaked lists' 48.9% / 50.1%. A ~14pp WR gap at a *higher* trade
count is not a sequencing difference — it is a generator that knew something at decision time
that it could not have known.

## Verdict

**REJECTED. The incumbent MTF OTE MNQ+MYM package is not live-ready, and never was.**

The 91.8% / 6.0% / 1.383 headline is a lookahead artifact, established by direct measurement
rather than inference: the same scorer, the same rules, the same 5 years, the same 15/1
geometry, and a leak-free generator produce **43.3% pass / 54.4% fail / funded-per-slot
0.623** — and **15.5% / 83.8% / −$104,692** once fills are costed per contract. The prior on
record (~10–18% pass) was correct in direction and roughly correct in magnitude at honest
costs.

**The farm currently has no validated live strategy.** The 2026-07-26 causal-parity audit
independently reached REJECT for the config that is actually deployed (MNQ 30/3 + 60/5), and
this memo closes the last remaining claim — the MNQ+MYM package the "live-ready" status was
built on. Every number descending from `*_london_enriched.csv` is void:

- `analysis/mtf_ote_exact_rule_scorecard.csv` / `data/mtf_ote_exact_rule_scorecard.csv`
- the 86.3% / 11.7% live-faithful headline (2026-07-19 memo, BACKLOG 0y)
- `data/firm_shape_scorecard_ote.csv` and the multi-firm scaling analysis that consumes it
