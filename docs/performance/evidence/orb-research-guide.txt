# ORB15 MNQ research package

Two standalone local scripts implement **Original** and the frozen **StopCap100** experiment with one-contract measurement defaults. Pine was compiled and executed in an isolated TradingView research chart; TOS native compilation remains unverified. No broker or routing connection was created. The files contain no alert functions, routing payloads, endpoint URLs or account credentials. Pine hypothetical order calls request alert suppression. Pine now rejects non-standard/synthetic chart types. TOS is disabled unless the symbol is exactly `/MNQ:XCME` and the user confirms a one-minute **time** chart. The numeric aggregation check alone cannot distinguish a 60,000-tick chart. TOS native compilation remains unverified. thinkScript `AddOrder` is hypothetical strategy reporting, not order routing.

## Frozen rules and risk formula

Use standard **one-minute MNQ time bars**, $2 per point and 0.25-point tick. Opening range uses all fifteen bars labelled 09:30–09:44 in America/New_York. It is known after the 09:44 close; at the 09:45 close both stop entries are staged, first eligible from 09:46. First direction wins; one entry per date, no re-entry. The original stop is the opposite range boundary and target is 5R from the actual slipped fill.

The source originally allowed `orBars >= 14` and variable sizing `floor(500/(range×2))` capped at 40. This package reproduces the **causal research baseline**: all fifteen opening minutes and exactly one contract. It does not reproduce original variable sizing or missing-opening-bar behavior.

Let `E` be filled entry including adverse entry slippage, direction `d` = +1/−1, and original opposite boundary `S0`. Set `R0 = d×(E−S0)`. Original mode uses `R0`. StopCap100 uses:

```
D = floor(((100 − 1.90 − 0.25×2)/2)/0.25)×0.25 = 48.75 points
R = min(R0, D)
stop = E − d×R
target = E + d×5R
```

Entry slippage is already inside `E`; expected exit slippage and fee remain in the budget. Binding planned benchmark loss is $99.90. This is a new experiment, not a source bug fix or live approval. Both modes leave the first fill bar unprotected: the bracket is submitted after the position becomes visible at that bar's close. At 15:59 close, orders are cancelled and a market closure is requested for the next available open, normally 16:00.

Costs are $0.95 per side, adverse one-tick entry/stop/market-exit slippage; target limits receive no adverse market slippage. Favorable target gaps can improve fills. A $100 planned budget is **not** a hard loss limit: gaps, the unprotected fill bar and actual market liquidity can exceed it. Fixed research capital is $50,000; Pine margin=0 deliberately measures exposure without native full-notional capital rejection. Neither file implements prop account rules, a trailing evaluation floor, funding eligibility or account reconciliation.

For a separately recorded doubled-cost comparison, Pine Properties can use $1.90 per side and two-tick slippage, keeping the 48.75-point cap unchanged. That manual sensitivity is not a new optimized parameter. TOS supplied source fixes benchmark costs; its custom dollar ledger includes fees, while Strategy Report marker P&L may not. Do not double charge fees or treat the report as a broker ledger.

## Platform differences that must be reconciled

Pine's emulator fills staged orders using its own historical OHLC assumptions and next-tick scheduling; its default closer-extreme path cannot be forced to the Python high-first/low-first scenarios by this script. Bar Magnifier, order-fill recalculation and close processing are disabled. Queued entry-stop activation and newly submitted protective-stop activation are carried from the previous close to the next open in the TOS model and revised oracle, including rebound bars. The two independent-review rebound fixtures now pass. Marketable-target limit rebound ordering and competing activated OCA/gap-open priority remain native parity limits; no exact equality is claimed. Inverted gap-entry geometry is explicitly rejected/flagged rather than silently assigned new exits. Entry, bracket, market-close/price-order priority, gap and price-rounding exports must be checked before calling the scripts equivalent. [Official Pine strategy documentation](https://www.tradingview.com/pine-script-docs/concepts/strategies/) and [current language reference](https://www.tradingview.com/pine-script-reference/v6/).

TOS `AddOrder` records an order for the **next bar**. The script therefore models completed historical OHLC fills in a custom state machine; AddOrder rows use the modeled price but markers occur one bar later. It is not a native resting OCA/bracket simulation. The custom net label computes $2/point and $1.90 fees; shifted marker timestamps and native Strategy Report are not authoritative execution records. TOS unsupported geometry/price-domain cases increment a prominent incomplete-model count; if nonzero, custom net is not a complete strategy result. Current incomplete-bar calculations can change, so no realtime confirmed-signal or alert reliability is claimed. [Official AddOrder documentation](https://toslc.thinkorswim.com/center/reference/thinkScript/Functions/Others/AddOrder).

TOS uses a single self-recursive packed state to avoid mutual recursion: 0 flat/unused, 1 flat/used, signed entry/stop tick integers for held positions. It supports positive frozen MNQ prices below 250,000 and US post-2007 daylight-saving dates; other domains are unsupported. It explicitly converts epoch minutes to New York minutes with the second-March-Sunday/first-November-Sunday rule. Cash-session winter/summer fixtures pass offline. However, `GetYYYYMMDD` returns a **trading-session date**, which can differ from the civil date for futures. Overnight/DST-transition/session-reset behavior still requires native verification. [GetTime](https://toslc.thinkorswim.com/center/reference/thinkScript/Functions/Date---Time/GetTime), [GetYYYYMMDD](https://toslc.thinkorswim.com/center/reference/thinkScript/Functions/Date---Time/GetYYYYMMDD), [GetDayOfWeek](https://toslc.thinkorswim.com/center/reference/thinkScript/Functions/Date---Time/GetDayOfWeek).

The TOS path selector is a predeclared OHLC uncertainty scenario, not an optimization control. HighFirst/LowFirst can alter first entry side when both boundaries are touched, and exit when both brackets are touched. Neither is a guaranteed outcome bound.

## Reproduce offline first

Extract the ZIP into a new folder. No packages or market-data download are needed:

```
python3 replay_fixtures.py
```

It writes `offline_validation.json`. The observed package run passed numerical fixture, cap, DST-clock, integer-encoding and static checks. These checks execute the Python oracle, **not Pine or thinkScript**. These offline results do not perform native compilation; separately recorded Pine native execution is described below. Fixture success does not validate an unseen compiler, feed, realtime bar or all native emulator paths.

The expected cases include:

| Case | Expected modeled behavior |
|---|---|
| Small stop/nonbinding cap | Original and capped geometry/fills coincide; favorable target gap improves price |
| Wide stop | Cap tightens stop to 48.75 points and sets 5R target; original retains opposite boundary |
| Fill-bar adverse excursion then gap | No fill-bar protective exit; next stop gap can exceed $100 |
| Both entry boundaries touched | First direction depends on frozen historical path |
| Both live exits touched | HighFirst/LowFirst give distinct feasible outcomes |
| 15:59 entry | Resting order can fill before close cancellation; EOD exits at next 16:00 open |
| Marketable entry rebound | Prior 09:45 close112 activates buy110; next open108 fills108.25 even with high109 below110 |
| Marketable protective rebound | Fill-bar close99 activates sell stop100; next open102 fills101.75 despite low101 above100 |
| Missing opening minute | Research eligibility rejects the day |
| 09:45 excursion | Orders created at that close cannot retroactively fill earlier in the bar |

Explicit neutral 09:45 and 15:59 calculation bars are added in fixtures when needed. This avoids silently assuming an order-submission bar existed. Fixtures are a price-path oracle; platforms cannot be assumed to ingest this JSON as native OHLC. Native reproduction requires matching exported bars or a separately verified synthetic-feed setup, not fabricating market prices.
